# Educational reader pilot — 24 November 2026

Continuation: [Phase 3 — shared six-subject reader](phase-3/REPORT.md). The record below describes the original pilot; general rollout remains disabled by default.

Implemented for `math/chapter2.html#section-02` (Mathematics: Linear Equations) only. No production rollout, content-package replacement, purchase/authentication changes, or changes to Lerona application code.

## Audit and implementation

- **Storage/delivery:** Cent stores source HTML, section HTML/text, and exercises in its database; originals are also embedded in the server assembly. Public curriculum responses contain outlines. Source sections require authentication and `CentAccess.RequireDocument`, including entitlement dates, revocation, publication, and reviewed-release checks for subject purchases. PDF uploads are converted by the admin browser with PDF.js into page images, stored in `cent_document_pages`, and delivered through authenticated page endpoints; the student reader paints images to canvas.
- **Working reader features:** page selection, table of contents, page-level last/furthest progress, 75–200% zoom, appearance control, visibility concealment, retry states, account-scoped notes, local unsaved text drafts, optimistic revisions, and note deletion. Reused these implementations.
- **Defects/limits:** imported HTML was displayed as plain text, losing nested fraction layout, semantic groupings and expandable answers. PDF canvas has no accessible text layer. Existing notes have only page and normalized vertical position; HTML reflow can move them. Clicking a location while editing previously moved the current editor instead of clearly creating a new note. Progress stores page rather than a text/scroll anchor; zoom is session state. Draft text is stored locally without its unsaved anchor. Existing source extraction also reorders some nested inline text, making the original HTML the appropriate pilot input.
- **Pilot presentation:** restores the existing source section verbatim from the embedded original, through the existing protected source-sections response. The fragment contains three worked examples, three exercises, definitions, fractional formulas, common mistakes and exam tips. It contains no illustrations; surrounding chapter diagrams remain outside scope. No mathematical text was rewritten or summarized. A strict DOM allowlist removes styles, URLs and executable elements before rendering; source classes map to scoped textbook typography, Sage example rules, compact tips and expandable answers. Persian uses the existing Vazirmatn fonts; English runs and formulas are direction-isolated. Existing Slate/Sage semantic tokens supply light/dark surfaces and colors. No content was added to public assets or the frontend bundle.
- **Annotations:** adds optional `AnchorJson` alongside existing `AnchorY`. New pilot notes store section-specific block IDs derived from text hashes, duplicate ordinal, a text quote fallback, and normalized x/y within that block. Resize/font/toggle observers restore marker geometry after reflow and zoom. Note selection scrolls to the block and opens enclosing answers; marker selection opens the editor. Existing notes retain their normalized page positions, bodies, IDs, ownership and revisions. Optional anchor metadata survives saves by older clients. No backfill or data deletion.

## Configuration and rollback

`Cent:ReaderPilot:Enabled=true` (environment: `Cent__ReaderPilot__Enabled=true`) enables only the exact section key above. Default is disabled. Other sections, including other sections of the same chapter, retain the existing reader. The flag is a presentation switch; access always goes through the original server entitlement checks.

Migration `20261124155704_ReaderPilotAnchors` adds one nullable `nvarchar(2000)` column to `cent_notes`; no existing rows change. Apply through the existing Cent migration process before using this backend build. It was **not applied to an existing/shared database**. Tests use fresh disposable SQLite databases. To disable the design, remove/set the flag false and retain the column/data. The migration has a Down operation, but dropping the column would discard new anchor metadata, so prefer flag rollback. Existing page/Y fallbacks remain usable after disabling the pilot.

## Security evaluation

| Delivery | Extraction and scraping | Unauthorized access | Reading/accessibility | Performance/cost | Annotations |
|---|---|---|---|---|---|
| Protected HTML (pilot) | Authorized users can copy DOM or network responses; automation is straightforward | Server checks required on every content request; existing checks retained | Best reflow, text selection, screen reader structure; formulas remain textual/CSS fractions | Small payloads, low rendering cost; current endpoint returns all chapter section text | Stable block/text anchors support responsive reflow |
| Protected PDF | An authorized recipient can save the original PDF; browser restrictions cannot prevent extraction | Must gate originals and ranges; never expose public URLs | Exact pagination; accessibility depends on tagging/text layer; narrow-screen reading often requires zoom | Larger downloads; little server rendering if served directly | Normalized page-relative coordinates are stable under scaling |
| Server-rendered images (existing PDF path) | Images are downloadable from authenticated network responses; OCR/screenshots remain possible | Existing access checks protect page bytes | Preserves visual layout; poor text accessibility/search/reflow | Stored page bytes and many requests; rendering/storage costs depend on resolution | Existing normalized page-relative Y remains stable under scaling; full x/y would improve precision |

Existing API responses use `private, no-store, max-age=0`, nosniff and no-referrer. Page requests are rate-limited (180/minute per configured partition); source-section requests have no equivalent dedicated content limiter. Page bytes are unwatermarked at the network layer; PDF watermarking is drawn client-side and HTML shows an account imprint. Right-click suppression and visibility hiding are deterrents, not extraction controls. Account holders can retain already delivered content after revocation; no-store does not revoke copied bytes. Local note drafts remain accessible to scripts running in the same origin. None of these residual risks was removed or represented as DRM.

Recommended follow-up: keep protected HTML for this review pilot; evaluate scoped source-response rate limits and section-at-a-time delivery, content revision IDs for anchors, private per-user watermarking on image responses if justified, and tagged PDF/text alternatives. If source revisions change wording, hash/quote anchors may fall back to approximate legacy Y and should be explicitly reconciled. Avoid promising prevention of screenshots/OCR or authorized extraction. No system-wide security overhaul was introduced.
